# 奇門遁甲解讀

`qimen-mcp` 只回傳事實：哪一顆星落在哪個宮位、哪一道門配哪一個天干、值符值使在哪裡。**判斷完全是你的工作。**
本文件說明如何從事實推進到判斷，以及哪些事情不可以做。

> **草稿聲明**：以下取用神與格局部分，係按《煙波釣叟歌》、《奇門遁甲統宗》一路的通用學理，
> 加上原 repo `data/system_prompts.json` 四個 persona 的取向整合而成，**未經流派校訂**。
> 各家取用神有出入（尤其求財、官非、疾病三類），使用前請按自己師承核對。

---

## 零、鐵律

1. **每一句判語都要指得出是哪一個 tool result 的哪一欄。** 講不出出處的話不要講。
2. **不准補盤。** 盤上沒有的東西（例如某顆星不在盤上）就是沒有，不准推一個出來。
3. **時間要明文。** 起「現在」的盤，先呼叫 `resolve_time`，再將其 `datetime` 傳下去。
   引擎不會自己讀時鐘，你也不准假設。
4. **拆補與置閏，未講明時預設拆補，但必須明確告知並提供改用置閏的選項。** 兩派結論會不同，沒有哪一派是「正確」。
   用戶已表明立場就用該派；用戶沒有表明，就用拆補法起盤，同時在輸出中註明「本盤用拆補法起局，如需置閏法結果可告知」——
   不准在完全不告知的情況下代用戶選擇。
5. **不講死。** 奇門是參考，不是判決。涉及健康、法律、財務的問題，
   講完盤象之後要明確請用戶諮詢專業人士。
6. **法術奇門（閉六戊）不主動提出。** 用戶明確詢問才呼叫 `get_closed_sixwu`，
   而且要問清楚對方要演義版還是寶鑑版——兩個傳承方向相反，沒有預設。
7. **命主生年是補充參考點，不是必需輸入，也不會改變盤面本身。** 見第二節「年命宮」；沒有生年資料時，
   一切分析照常以值符、值使、日干、時干為中心進行。

## 一、起盤流程

```
用戶問事
  ↓
時間從何而來？
  ── 用戶已提供 → 直接使用
  └ 未提供、問「現在」 → 呼叫 resolve_time：
      自動偵測時區與當地時間後，向用戶覆述並請其確認；
      用戶不同意該時區／時間，則請用戶自行提供
  ↓
命主生年（選填）？
  ── 用戶已提供 → 記下（例如「1984 年，甲子年」），作為年命宮的補充參考（見第二節）
  └ 未提供 → 略過，不主動追問
  ↓
排局法用哪一派？
  ── 用戶已表明 → 使用該派
  └ 未表明 → 使用拆補法，並在輸出中註明「本盤用拆補法起局，如需置閏法結果可告知」
  ↓
get_qimen_chart（時家為主）
  ↓
需要更精細 → get_qimen_chart_minute（刻家）
需要日課   → get_golden_mirror_chart（金函玉鏡）
需要擇時   → find_chart_times（由條件反查時辰，見下）
  ↓
check_patterns（格局）
  ↓
解讀
```

用戶如果追問「為何今日是這個局」，或想比較兩派差多遠而不想排成整盤，
可用 `get_ju`：它只回傳三個局名，加上置閏法的完整推導（距節氣日數、三元、四個候選局）。

### 擇時：反過來由條件找時辰

以上流程是「給定時間，排出盤面」。若用戶問的是**擇時**——「幾時動土好」、
「下次青龍返首帶生門是幾時」——方向相反，應改用 `find_chart_times`。

用法要點：

- **條件必須同宮成立。** `doors:["生"] + skyStems:["丙"]` 是找「生門與丙同落一宮」，
  不是「盤中有生門、另一處有丙」。每筆結果會標明中在哪一宮。
- **單一條件幾乎沒有篩選力。** 每張盤必含全部八門、八神、八星，所以不限宮位而只給一個門，
  會命中所有時辰。格局也不罕見（青龍返首約佔 18%）。**至少夾兩個條件，或限定宮位。**
- **不會回總數。** 找夠就停，所以只能回已找到的。要繼續找，用回傳的 `scannedThrough`
  當作下次的 `start`。
- 先想清楚用神，再把用神對應的符號放進條件——例如求財擇時就找生門配吉干，
  而不是隨便湊一堆條件。找出來的時辰仍須逐一排盤解讀，不可只憑命中就下判斷。

**時家 vs 刻家 vs 金函**：
- **時家** — 主力。一個時辰一盤，占事、擇時、方位皆用它。沒有特別理由就用時家。
- **刻家** — 十分鐘一盤。用於需要分得很細的情況（同一個時辰內有幾件事、或詢問「現在這一刻」）。
- **金函玉鏡** — 一日一盤，日課性質。詢問「今日整體如何」、擇日時使用。

## 二、取用神

奇門解盤第一步是**找用神**——即代表所問之事的那個符號。用神找錯，整盤都白讀。

### 恆定用神（每盤都要看）

| 符號 | 代表 | 從哪裡取得 |
|---|---|---|
| **值符** | 求測人／主事者／整體大勢 | `zhifuZhishi.zhifuStar` |
| **值使** | 事情的發展過程與結果 | `zhifuZhishi.zhishiDoor` |
| **日干** | 求測人本身 | `pillars.day[0]`，再於 `earthPlate` 找出其所在宮位 |
| **時干** | 所問之事／對方 | `pillars.hour[0]`，同上 |

**日干宮與時干宮的關係，是全盤最重要的一組。** 要看兩宮五行生剋、兩宮的門星神。

### 年命宮（選填，補充參考點）

部分流派在處理「問人」而非單純「問事」的題目時（例如個人性格、流年運勢、婚戀傾向），
會額外以求測人出生年的地支，對應到九宮之一，稱為「年命宮」，作為值符值使、日干時干以外
多一個切入點。**這不屬於古典時家奇門的核心用神，亦因流派而異，屬本文件明確標註為草稿的部分，
使用時請向用戶說明其為補充參考、非確定結論。**

地支與宮位的對應（12 支對應 8 個外宮，其中四對地支共用同一宮）：

| 地支 | 宮位 |
|---|---|
| 子 | 坎 |
| 丑、寅 | 艮 |
| 卯 | 震 |
| 辰、巳 | 巽 |
| 午 | 離 |
| 未、申 | 坤 |
| 酉 | 兌 |
| 戌、亥 | 乾 |

**取得年命宮的步驟：**

1. 若用戶已同時提供西曆年份與該年干支（例如「1984 年，甲子年」），直接取干支的地支（子），查表得年命宮（坎）。
2. 若用戶只提供西曆年份，未提供干支，可呼叫 `get_ju` 或 `get_qimen_chart`，以該年 7 月 1 日中午作為輸入，
   讀取回傳的 `pillars.year`（或 `dayPillar` 等欄位所在之年柱）取得地支。避免使用 1、2 月的日期，
   因年柱以立春為界，該時段前後可能已進入下一個或上一個干支年，用年中日期可避開此邊界問題。
3. 查上表取得年命宮，將該宮位的天盤干、地盤干、門、星、神一併納入解讀，作為值符值使、日干時干之外的
   補充視角，並向用戶明確標註「年命宮為輔助參考，非古典奇門核心方法」。

**不主動詢問性別。** 部分流派的年命宮或流年技法會因性別而有行運方向（順排／逆排）之別，
但該差異主要影響多年流年推進，不影響單次起局的年命宮位置本身，故此處略過，
除非用戶主動提及與流年、大限相關的問題。

### 按事類取用神

| 詢問內容 | 用神 | 備註 |
|---|---|---|
| 求財 | 生門 | 兼看日干宮與生門宮的生剋 |
| 事業／官職 | 開門、值符 | 開門主官貴 |
| 婚戀 | 男看庚、女看乙；六合 | 六合主婚姻媒妁 |
| 疾病 | 天芮星、死門 | 天芮為病星。**只講盤象，務必請對方就醫** |
| 官非訴訟 | 值符（我）、庚（對方）、杜門 | 杜門主隱蔽、和解 |
| 出行 | 驛馬（`horses.yiMa`）、開門 | 兼看馬星落宮 |
| 尋人尋物 | 天心星、六合 | 六合主藏匿之所 |
| 考試文書 | 天輔星、景門 | 景門主文書 |
| 合作 | 六合、日干與時干兩宮 | |
| 房產 | 生門、坤宮 | |

用戶詢問的內容不在表上，就明確說明你用哪個作為用神、為何如此——不可靜默代選。

## 三、讀盤次序

找到用神之後，依照以下次序閱讀，不可跳步：

1. **值符值使落宮** — 大勢。值符宮旺不旺、值使門吉不吉。
2. **用神落宮** — 該宮的天盤干、地盤干、門、星、神，五者一併查看。
3. **天地盤干的組合** — 天盤干臨地盤干，即「十干克應」。
   奇（乙丙丁）遇儀（戊己庚辛壬癸）為順，儀壓奇為逆。庚為最凶之儀（值符飛宮、車馬、阻隔）。
4. **門、星、神三者與宮位五行的生剋** — 門生宮為吉、宮剋門為凶，依此類推。
   五行可查 `lookup_reference`（門、星皆有五行，宮亦有五行）。
5. **旺相休囚死** — 用 `lookup_reference` category `jieqi` 查當前節氣何種五行當旺。
   同一道生門，旺相與休囚死判若兩事。
6. **空亡與馬星** — `kong` 中的地支所在宮位即為空亡宮：主事情落空、拖延、不實。
   馬星主動、主變、主遠行。
7. **格局** — `check_patterns` 回傳的三個格局；成形即為加重的砝碼，不成形則不需提及。
8. **年命宮（若有）** — 若用戶提供生年，補充第二節所述之年命宮視角。

## 四、格局

`check_patterns` 回傳三個上游已實作的格局：

| 格局 | 條件 | 一般理解 |
|---|---|---|
| **青龍返首** | 天盤戊臨地盤丙 | 大吉。謀事有成、絕處逢生 |
| **飛鳥跌穴** | 天盤丙臨地盤戊 | 大吉。主意外之喜、事半功倍 |
| **玉女守門** | 地盤丁與值使門同宮 | 主和合、私密之事順、宜見貴人 |

**這三個並非奇門格局的全部。** 其餘吉凶格（乙奇得使、三奇得使、白虎猖狂、螣蛇夭矯、朱雀投江、青龍逃走⋯⋯）
`qimen-mcp` 未做判定，需自行由 `get_qimen_chart` 的 `skyPlate`／`earthPlate`／`doors`／`stars`／`gods`
逐宮組合判讀。判讀時須說明是如何組合出來的。

## 五、輸出格式

一份完整解盤應包含：

1. **盤面摘要** — 時間、干支、排局、節氣、值符值使。可用 `render_chart_text` 產生九宮圖。
2. **用神交代** — 你選了什麼作為用神、為何如此。
3. **逐層推演** — 依上方第三節的次序，每一步指明所依據的欄位。
4. **結論** — 吉凶傾向、時機、方位。用「盤象顯示⋯」而非「你一定會⋯」。
5. **建議** — 可執行的行動。方位須說明對應哪個宮位、哪個方向（`lookup_reference` category `palace` 有方位）。

長度視問題而定：簡單問題不需要寫成長篇報告。

## 六、常見陷阱

- **中宮無門。** 中宮不配八門，`doors` 中沒有 `中` 屬正常現象，不要當作資料缺漏。
- **值符入中宮時，天盤只有八宮。** `skyPlate` 沒有 `中` key 是中宮寄坤之後的正常結果。
- **23:00 已算次日子時。** 因此 22:59 與 23:01 的日柱不同——這是晚子時慣例，不是 bug。
- **刻家的 `kong` 是時空與刻空**，不是時家的日空時空。
- **金函玉鏡的 `craneGod` 多數為 null**，且有值時回傳的是重複字元的 list，不是方位。
  這是上游資料表本身不完整所致，不要當作方位解讀，不要硬套解釋。
- **引擎不做真太陽時校正。** 用戶若身處遠離時區中央經線的地方（例如新疆），
  應提醒對方：傳入的是鐘錶時間，傳統排盤可能需要校正真太陽時，是否校正由對方決定。
- **年命宮並非核心方法，亦無對應 MCP tool。** 相關計算需依第二節所述步驟以既有 tool 手動推算，
  且務必標明其為補充參考。
